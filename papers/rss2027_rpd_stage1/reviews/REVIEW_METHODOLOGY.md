# Independent methodology assessment

This is a computational manuscript review, not external referee endorsement. I read `manuscript/main.tex`, `manuscript/body.tex`, `manuscript/references.bib`, and the rendered Figure 1 independently of earlier reviews. I also inspected the pinned local ManiSkill source as text. I did not import ManiSkill, construct a simulator, run physics, install dependencies, or modify Git or manuscript files. Line references below refer to `manuscript/body.tex`.

## Overall assessment

The paper defines an intelligible prospective question and appropriately limits its novelty to a measurement and validation methodology. Its separation of partial option loss from full-repertoire erasure, common remaining deadline, all-parent denominators, shared-model controls, and explicit acknowledgment that task-consensus equals RPD are substantial strengths. Figure 1 accurately illustrates the constructed example and marks it as conceptual. Proposed assembly defaults are consistently distinguished from qualified physical settings; there is no assembly evidence in this manuscript.

The protocol is not yet a fully executable, self-contained preregistration. Several decisions below can change the estimand or the policy being evaluated, rather than merely implementation details. They should be fixed in text and a frozen configuration before simulation qualification. The main unresolved empirical questions are whether the source can generate the declared cohort, whether replay is valid, and whether these two specific corrections produce any informative full erasure. A simulation-only next stage is reasonable after these corrections; no hardware campaign is needed to answer the stated restricted question.

## Ranked defects and actionable corrections

### 1. High: matched time does not isolate a physical mechanism when recovery depends on branch-specific diagnosis

Lines 52–63 describe physical loss relative to holding, but `a1` uses a posterior-mean post-probe grasp transform (line 102). Probe and hold therefore change both the physical start state and the parameters of the subsequent corrective trajectory. A poorer posterior can cause `a1` to fail even if probe and hold leave the same physical state. Conversely, a better estimate can create an available option without improving physical clearance. The present contrast is a valid total intervention effect on the declared deployed policies, but is not automatically an effect mediated by physical state displacement.

**Correction:** Choose one interpretation explicitly. For a physical-loss primary estimand, bind the corrective policies so their recovery parameters do not depend on the preceding diagnostic response, while allowing the selector to choose between them using that response. Alternatively retain the response-conditioned correction, rename the estimand as total branch-induced loss of deployed recovery options, and add a prespecified common-information/common-recovery-parameter audit before attributing loss specifically to physical motion. In either version, include estimator memory and policy-relevant observation history in the state used to define `K`; physical state, controller memory, and a separate unspecified `h` are insufficient to determine this `a1`.

This correction does not require claiming an observation-conditioned policy is illegitimate. It requires matching the causal wording to what is held fixed.

### 2. High: the finite model does not specify the outcomes of response-conditioned recovery consistently

Lines 111–113 define a channel `P_p(j | i)` with positive probability for multiple codewords `j` at physical particle `i`, then obtain one recovery outcome per physical branch and action. However, the target of `a1` depends on the posterior after the observed codeword. The rollout labeled at particle `i` under its own actual response need not equal the rollout at that same physical state under the posterior induced by another `j`. In general the required quantity is `G(i,p,j,a)`, not just `G(i,p,a)`. Reusing the latter in Equation (5) can make RPD optimize an internally inconsistent model. An independent enumeration of the same inconsistent table would still agree algebraically.

**Correction:** State exactly which observation/history is supplied to each recovery-label rollout and which information its target generator uses. The economical solution is to make both declared corrective routines independent of the diagnostic posterior; the present particle-by-action labels then suffice. If response-conditioned recovery is essential, include that conditioning in the transition/outcome model and explicitly account for the resulting label budget, or provide and freeze an approximation with a clearly stated limitation. Equality controls should enumerate the same fully specified contingent policy, including the recovery parameter computation, rather than only repeat the outer maximization.

There is no unavoidable model-training circularity once a response model is frozen before collecting labels. The current freeze order is a good start. The unresolved issue is the contract between that model, each label, and the response-conditioned execution.

### 3. High: the source pilot requires a recovery model that does not yet exist

The source pilot precedes population work and executes seven matched/direct branches (line 115). Yet `a1` requires a frozen observation model and post-branch transform labels, which are collected during discovery (line 111). The direct policy is also not named before those models are fitted. A nominal transform, a prior mean, or a true transform would each produce a different pilot and could change source qualification.

**Correction:** Bind an explicit dependency order. For example, use a named, response-independent nominal recovery solely for mechanical source qualification; assess replay and executable command validity there, without interpreting its successes as the final policy's performance. Then collect the fixed discovery responses, freeze the observation model, collect final-policy labels, and freeze selectors before confirmation. Alternatively specify a separately fixed bootstrap model and account for all data used to fit it. State whether the pilot's seven branches are the final policies or qualification-only policies. Qualification must continue to avoid gates on erasure, classifier accuracy, or RPD advantage.

### 4. High: the native episode time limit conflicts with the declared deadline

The pinned source registers `PegInsertionSide-v1` with `max_episode_steps=100` (`mani_skill/envs/tasks/tabletop/peg_insertion_side.py:50`). At 20 Hz this is five seconds from reset. The declared 0.5 s gripper close plus 1 s approach plus 4 s recovery budget requires 110 control updates; the doubled-budget sensitivity requires 190. A stock wrapped episode can truncate before the declared common deadline. In particular the longer correction's stable-hold measurement can be affected.

**Correction:** Explicitly override or remove the Gym and ManiSkill time-limit wrappers for this study, or set the limit above the longest complete prefix plus deadline. Preserve the absolute elapsed clock; do not reset it at the checkpoint. Specify that a sampled violation or task flag does not silently end physical stepping when the estimand requires monitoring through the deadline. Distinguish STOP, task completion, constraint violation, infrastructure failure, and wrapper truncation in the terminal record.

This is a source-visible execution-contract issue, not evidence that the proposed mechanics will fail.

### 5. High: initial transforms and recovery trajectories are not yet unique

Lines 91–95 give useful dimensions, frame locations, rotation, and error magnitudes, but they do not provide the ordered rigid transforms. With a peg half-length `ell`, a nominal head at `-ell-2c` implies a nominal center at `-2ell-2c`; a reader could instead place the center at the stated head coordinate. Likewise a pitch/yaw error composed about the peg center differs from one composed about the TCP 60 mm behind it. Perturbing a grasp transform does not resolve whether translation is expressed in hole, peg, or TCP axes, or whether rotation is left- or right-multiplied. “Source home vector” could refer to the task initialization or the Panda rest keyframe; their final arm joint signs differ in the inspected source.

Line 102 also leaves the orientation and precise TCP target for `a0` implicit. `a1` needs the full pose used at each waypoint, the treatment of posterior rotational averaging, and an explicit definition at the root and after hold. A mean of rotations is not uniquely specified by “posterior mean.”

**Correction:** Publish a small transform table/equations for `T_WH`, `T_HPeg_nominal`, `T_WTCP`, `T_TCPPeg_actual`, and the exact perturbation composition and pivot. Give the nine-coordinate initialization vector, zero velocity convention, gripper initial command, and IK seed/acceptance metric. For every recovery phase, give target peg pose, conversion to TCP pose, orientation behavior, start pose, duration, and interpolation rule. Specify how a multimodal rotation posterior becomes an executable rotation and how ties are handled. This can be a compact protocol appendix/configuration, but these definitions must be available to reproduce the paper.

### 6. High: continuous probe formulas need a discrete execution and sampling contract

There are ten 20 Hz control updates during a 0.5 s probe (line 100), but the paper does not say whether the command at update `k` uses `t=k/20`, `(k+1)/20`, or a midpoint. Sampling the sinusoid at `0,...,0.45` seconds leaves a nonzero final equilibrium; sampling it at `0.05,...,0.5` seconds returns the equilibrium to zero. A subsequent macro can thus begin with a different commanded equilibrium. The same ambiguity affects cubic interpolation, the terminal endpoint, and the hold comparison.

`Y_p` is described as ten samples of a response observed at 100 Hz (line 108), without choosing which substep samples constitute those ten. Constraint/goal checks at 100 Hz also need a hook inside each native 20 Hz control step, rather than a once-per-step evaluation after five simulation substeps.

**Correction:** Specify the command indices, zero-order hold intervals, exact endpoint policy, sample timestamps relative to command application, and observation order. Define the ten `Y` samples as named substep samples or fixed aggregations. Define the contiguous stable-goal dwell calculation in simulation ticks, including boundary inclusivity and when the flag is set. Include one table of expected command counts and final commanded pose for hold, preload, dither, and each correction. Bind this before observing any outcomes.

### 7. High: checkpoint parity is assumed but the replay mechanism is unspecified

Lines 63 and 115 correctly require complete physical/controller replay, fresh processes, and repeatability. However they do not state whether branches regenerate the entire fixed prefix or restore a snapshot. The native environment's `get_state_dict`/`set_state_dict` should not be assumed to establish the required parity. The inspected absolute pose controller defaults to `use_target=False`; its `get_state` returns no target state, and native environment state is not a complete serialization of command history, task dwell state, absolute clock, or solver contact memory.

**Correction:** Choose fresh-process fixed-prefix regeneration or a verified full serializer. Prefix regeneration is the simpler prospective route: replay identical initialization and commands to the checkpoint, record physical and controller fingerprints there, and branch only afterward. Bind tolerance checks at the root as well as at terminal times, including commanded target, joint drive target, gripper state, elapsed steps, estimator state, completion dwell state, and goal/violation outcomes. Do not treat an ordinary successful pose restore as sufficient evidence. Record any replay failure as missing for the fixed eligible parent under the declared inference rule.

The two repeated eligible IDs provide only a bounded engineering qualification. They cannot establish deterministic replay throughout the later distribution; continued parity auditing and explicit uncertainty remain necessary.

### 8. Medium-high: bind the selector's action domain and direct/STOP conventions

The physical contrast defines `J_p` for a probe and its duration-matched hold, whereas IG and RPD can choose direct recovery or STOP (lines 48, 59, 113). `q_IG = E[J_piIG]` therefore needs an explicit no-probe convention. It is also unclear whether physical hold is itself an available diagnostic action or only an evaluator control, and how IG ranks zero-information direct recovery and STOP against a modeled admissible probe with zero information.

**Correction:** List the selector's actual candidate actions, gate, objective, post-response recovery rule, and total tie ordering. Define `J=0` on a direct/STOP decision if H1 means erasure caused by an actually selected diagnostic intervention. Otherwise define H1's probe-only selector separately and retain the full predecision population denominator. State the root posterior/transform used for direct `a1`. Explain why one direct rollout per confirmation parent suffices: all compared methods must share the same response-independent root recovery choice, or additional root actions must be evaluated. Bind the modeled path-risk calculation and whether it gates the entire contingent strategy or individual response branches.

### 9. Medium: observation-free action choice is not necessarily observation-free recovery

The response-blind rule in line 122 is scored on the existing post-probe action outcomes. This is a useful action-selection control, but if those outcomes are for `a1` parameterized by the diagnostic posterior, the control still uses the response inside recovery execution. Its difference from RPD cannot establish the total value of diagnostic response information.

**Correction:** Call this specifically the value of response-dependent catalogue choice while holding response-dependent execution fixed. If the intended question is the complete decision value of the response, freeze the response-dependent recovery parameters too, and include the extra rollouts in the budget. A response-independent corrective catalogue resolves this issue together with defects 1–2.

### 10. Medium: fixed accounting is mostly sound, but timing, attrition and fitting budgets need a manifest

The stated base terminal accounting is internally consistent: 3,072 confirmation matched recoveries + 512 shared direct-policy outcomes + 512 discovery recoveries = 4,096. Observation-only collection and screening are explicitly additional, and branches are correctly distinguished from independent parents. The 98-episode pilot bound also matches 12 times seven plus two times seven repeated branches. These are meaningful improvements over an unbounded successful-parent search.

Remaining gaps are operational. The discovery model must define how rejected/missing discovery candidates affect particle count, response codebooks, equal fitting budgets and training failure. The SHA-derived seed does not alone define the candidate manifest, RNG draw order, rejection implementation, or phase/index strings. A timeout during screening leaves eligibility unknown, rather than automatically establishing a scientifically ineligible root. The 28 worker-hour ceiling gives no prespecified execution order once confirmation eligibility is known, and no primary-work per-episode timeout/concurrency contract. A runtime-selected prefix with worst-case missingness is conservative but can easily yield no useful inference.

**Correction:** Freeze the candidate IDs, phase names, seed encoding, RNG namespaces/draw order, output manifest, execution schedule, timeout policy, worker counting, and failure taxonomy. Distinguish known predecision ineligibility, unknown eligibility, and missing outcomes of known eligible parents. Give a conservative rule for unknown eligibility or explicitly restrict the target population to a computationally screenable source definition. Bind a minimum discovery dataset/model-fit validity criterion that does not depend on effect size. Use qualification runtime measurements only to decide whether the already fixed study can fit its resource ceiling; if it cannot, report source/resource unqualification or design a newly versioned study rather than begin an outcome-selected confirmatory prefix.

### 11. Medium: preserve the difference between goal-based and compliant recovery availability

The paper correctly states that goal completion does not imply path compliance (line 29), and `J_p` checks probe and hold compliance, not successful-recovery compliance. Thus a hold branch may have an available goal-reaching correction that violates the path constraints, and still contribute to “compliant repertoire erasure.” This is mathematically consistent with the written definition but easy to overinterpret as destruction of a safely usable recovery.

**Correction:** Keep the primary goal-based definition explicit in every interpretation, or add a second clearly named set requiring both goal achievement and recovery-path compliance. Report the two complete option masks and their losses separately; do not silently change `G` after outcomes. Specify whether violations merely mark a path or abort it, and how completion after an earlier violation is recorded. The proposed force/slip thresholds should remain labeled sampled simulation constraints, not qualified safety limits.

## Exact uncertainties that require experiments

The following cannot be resolved by manuscript editing or static source inspection. Each should have a separately reported result, including failure or null results:

1. **Source accessibility:** At the specified world/base poses and error transforms, does CPU IK converge under the declared residuals without forbidden initial overlap, and do the unwelded finger contacts retain the peg during closure and approach? Measure IK acceptance, collision/constraint attrition, native grasp status, source checkpoint residuals and forces on all 12 fixed qualification IDs. No outcome-based geometric retuning is implied.
2. **Eligible population size:** Do at least eight of those roots meet the fixed predecision contact/constraint definition? Later report eligibility and unknown-eligibility counts for all discovery/confirmation IDs. Do not infer a high yield from the nominal perturbation scale alone.
3. **Replay and controller continuity:** Do fresh-process prefixes reach matched checkpoints within the declared tolerances, and do repeated terminal paths preserve commands, clocks, goals and constraint outcomes? This must be measured with the final discrete schedule and correct wrapper configuration.
4. **Execution and runtime:** Can all recovery macros run with native CPU IK at the declared substeps, can evaluator-only impulses/forces and 100 Hz monitoring be collected, and does the fixed branch plan fit the resource ceiling including initialization/process overhead? Static source confirms the interfaces, not their runtime feasibility or stability.
5. **Diagnostic signal:** Do proprioceptive arm/TCP responses improve held-out prediction of the declared generator mode beyond `X` and matched hold? Mode prediction is the stated endpoint; it is not automatically identification of signed grasp error or recovery-relevant state. Measure the frozen proper-score contrasts and predictor calibration/error.
6. **Recovery repertoire:** Does either declared correction complete the stable held mid-depth goal at any appreciable frequency, and does the probe erase the *entire* repertoire rather than only one policy? Measure full hold/probe option masks, creations, partial losses and erasures. Source validity must not depend on obtaining a favorable answer.
7. **Mechanism attribution:** For an observed loss, is failure explained by physical post-branch state change, diagnostic estimation/parameter changes, or a deadline? This needs the prespecified information-standardized audit and doubled-deadline sensitivity if a physical causal interpretation is retained.
8. **Prediction and policy value:** How well does the fixed finite model predict actual option outcomes/violations, does the contingent implementation agree with the independent equality control, and does the held-out completion difference meet H2 without exceeding the violation margin? Training fit and algebraic equality alone cannot answer these.
9. **Precision:** With actual eligible count and missingness, are H1's lower bounds and H2's paired intervals informative? The paper appropriately avoids treating the binomial-component power as joint H1 power. A qualified null, an underpowered interval and an unqualified source must remain distinct outcomes.

## Feasible simulation-only next stage

First repair the estimator/label contract, exact transforms, discrete timing, wrapper limit and pilot dependency order in a frozen protocol. Then run only the fixed bounded source qualification, with a failure report if its source/parity/runtime criteria fail. If it passes, perform the fixed discovery collection and freeze the complete observation model, recovery policy implementations, gates, selectors and execution manifest before confirmation. Collect the full predeclared cohort with all missingness retained, then report the complete option masks and matched task-aware controls alongside H1/H2.

The evidence would remain specific to CPU simulation, the chosen geometric generator, two declared corrective policies, the held mid-depth goal and the deadline. A positive H2 would establish the proposed comparison with constrained IG, not algorithmic superiority over equivalent task-aware contingent planning. A positive full-erasure estimate would establish catalogue-relative loss, not physical irrecoverability under all possible controllers.

## Assessment of the proposed correction communicated after this independent read

After the initial assessment was written, the coordinating editor proposed computing a grasp-transform estimate once from legitimate root `X`, fitting that estimator from discovery root states before recovery-label collection, and storing it unchanged through every probe, hold and direct branch. The editor also proposed exact initialization transforms, updates `k=1,...,10` with targets evaluated at `k × 0.05 s`, explicit phase definitions, a 200-control-tick task limit, and fresh fixed-prefix regeneration.

The frozen-root estimate addresses defects 1, 2 and 9 in substance: response can change the selected correction, but cannot alter either correction's parameters; outcomes indexed by physical particle, branch and action are then coherent. The estimator itself must be frozen before labels, its stored estimate must be included in replay fingerprints, and no response-derived parameter update may occur during a recovery. Fitting the remaining shared finite model after those labels does not introduce a circular definition under that ordering.

A 200-tick wrapper limit accommodates the 30-tick close/approach prefix plus 160-tick doubled deadline with ten ticks of headroom, provided there are no uncounted settling commands and both relevant wrappers use that limit. Explicit endpoint and sample scheduling resolves the command ambiguity only when observation and monitor timing are also bound. Fresh fixed-prefix regeneration avoids relying on an unverified snapshot serializer; its parity still requires the stated empirical checks.

These are assessments of the communicated proposed fixes, not evidence that the manuscript or implementation has already incorporated or experimentally qualified them. The source-pilot/estimator dependency, full action-domain conventions, unknown eligibility and fixed execution manifest still require explicit resolution unless addressed separately. None of the proposed corrections establishes physical source feasibility, replay validity or H1/H2 effects.

## Final revised-manuscript closure assessment

I reread the revised `manuscript/body.tex` in full. Its SHA256 at this assessment was `b31439a5a34567f31b43f9d52a4c6c5c7b28d51c581716376e5016db0bd30dbe`. This section assesses that exact text and supersedes the earlier unresolved-status list where revisions now address it. I again performed no simulator import, physics execution, installation, Git mutation or manuscript edit.

**The principal methodology objections are resolved in the written protocol.** The root-only estimator is fit before labels and frozen across direct/probe/hold branches (lines 109, 118–120), so diagnostic responses choose a policy without changing that policy's parameters. This makes the physical intervention interpretation and per-particle outcome labels coherent within the declared model. The nominal qualification bootstrap precedes discovery, with final-estimator parity afterward (line 124); no model is now required before its own source data exist. The 200-tick wrapper override covers both declared horizons (line 95). Initial centers, angular pivot/composition, task home vector and velocities are explicit (lines 98–104). Endpoint-inclusive commands, substep response samples and the 26-sample dwell rule substantially close the timing ambiguity (lines 107–111).

Fresh-prefix replay with root fingerprints, command/clock checks and continuing parity audits is now the declared mechanism, rather than presumed snapshot validity (lines 124, 127). H1 has an explicit probe-only selector and abstention contribution, distinct from H2's direct-recovery wrapper (lines 63, 122). Goal-based and compliant-recovery masks are distinguished (line 59), unknown eligibility prevents an unconditional eligible-population claim (line 127), and the fixed execution order/timeout is stated (line 129). Response observations now come from the same terminal rollouts; an extra response-only pass is unnecessary. Under complete eligibility the base accounting is 4,096 terminal + 576 screening + 16 final-estimator parity + at most 110 qualification source episodes = **4,798 source episodes**, before optional horizon sensitivity. The 110 includes at most 12 qualification screens plus its 98 terminal episodes.

### Remaining writing/definition items before executable freeze

1. **Final-estimator parity ID selection:** Line 124 says “the first two discovery IDs,” whereas the minimum discovery requirement permits known ineligible earlier IDs. Use “the first two eligible retained discovery IDs in ascending order.” Otherwise those parity branches are undefined when ID 0 or 1 is ineligible. The earlier nominal pilot already selects its repeats among eligible IDs.
2. **Meaning of a common direct action:** Line 122 should state the exact test. If intended, define availability as `G_i(root,a)=1` for every retained positive-weight particle; choose among such actions by the declared deterministic ties. This differs materially from positive modeled expected success. Also make clear that the fallback root argmax is taken over both direct policies, with STOP selected when their modeled completion values are zero. The surrounding description strongly suggests this behavior, but the implementation should not infer it from the word “common.”
3. **Minor metric/scope conventions:** Explicitly call the initialization IK orientation residual geodesic, and state that its iteration cap/acceptance test use the same TCP/base transform as the commands. Bind whether path-violation probability in H2 covers only checkpoint-to-deadline paths or also setup; the clean comparison is the former with setup failures/violations reported separately as source disposition. Define grasp-slip translation/rotation using the relative peg-in-TCP transform so it cannot be confused with world displacement. These are small local clarifications, not reasons to alter thresholds or search parameters.

I find no remaining major conceptual blocker to a **bounded simulation source qualification** after these local definitions are frozen. This is not a conclusion that source qualification has passed, that the study is powered under actual attrition, or that the approach is publishable without its prospective results. In particular, the minimum of two discovery particles prevents an undefined model but provides no adequacy guarantee; report its predictive errors and all unavailable/weak-inference outcomes as already promised.

### Remaining physics-only and empirical uncertainties

The initial uncertainty list still applies to native IK reachability, initialization contact validity, grasp retention, eligible-root yield, exact per-parent replay, force/monitor availability, source stability and runtime. The revised controls cannot establish these by definition. A 200-tick wrapper limit fixes the clock contract but does not establish IK tracking or physical stability. Root fingerprint tolerances and the two-ID parity check require measurements, not textual approval.

Likewise, no written correction establishes held-out diagnostic score improvement, successful recovery under either fixed policy, material full-repertoire erasure, useful common direct actions, accurate model predictions, a completion advantage, constraint noninferiority or informative confidence intervals. Those are precisely the fixed simulation study's outcomes. No experimental gate should be added to require favorable versions of them. The manuscript now explains these limits substantially better and preserves a defensible simulation-only, catalogue-relative interpretation.
